## Shared contracts

### A. Floor metadata, separate from object edits

Add `DescriptionPatch.floor_metadata_updates`, default empty for old persisted patches. Each update identifies an existing `floor_id` and contains explicit typed field changes plus positive-area original `evidence`, a nonempty `reason` and applicable `issue_ids`. Suggested shape:

```
{floor_id, changes:[{field, value}], evidence, reason, issue_ids}
```

Use a discriminated typed change by allowed metadata field: label, source, order/order_basis, rotation/orientation_basis, calibration, alignment, registration and height. The implementation may reuse the existing typed values; the operation contains no rooms/boundaries/openings/features/unresolved/measurements lists, no persistent-ID assignment and no view-type conversion. All unspecified metadata and all nested inventory remain exactly unchanged. A nullable field is cleared only by its explicitly present typed change with `value:null`; an absent field or model default never clears it. Duplicate edits of the same metadata field, unknown fields and nested arrays reject atomically. Source/frame/provenance validation applies to the assembled candidate exactly as today; explicit transform updates remain mandatory when the source/display frame changes.

The new provider contract must use this operation for existing-floor metadata. Existing nested-object operations remain independent, order-insensitive where they affect distinct fields, and fully validated. Supported floor addition/removal capability remains in the existing operation path; this pass must not prohibit genuine depicted floor additions. Legacy full-floor replacements remain parseable with their strict nested-array guard for historical replay and callers; do not silently discard copied nested changes, strip arrays from bad historical patches or convert them into successful metadata edits. A newly returned legacy full-floor payload that fails gets actionable feedback requesting the new metadata operation.

Gemini's known wire restrictions still apply: use the existing JSON-string adapter pattern if the typed value union is not wire-compatible; decode and validate locally without weakening types. Do not introduce unsupported numeric schema constraints, arbitrary generic objects or a full copied floor as a workaround. Freeze exact Python/wire names with root before dependent edits.

### B. Safe local feedback and reviewed additional targets

Introduce structured `PatchRejection` diagnostics for recoverable application validation: stable code, operation/metadata-update index, implicated field/target/floor/issue IDs, safe explanation and concrete expected contract. Examples are missing typed record, wrong collection, floor metadata containing nested edits, target outside reviewed scope, no material change and conflicting operations. Include the rejected proposal hash and pinned base revision. Do not expose private requests, arbitrary exception text or model thoughts. Public UI gets a concise actionable summary; private job history retains the typed feedback/proposal and safe call diagnostics.

Preserve all validators. Recovery catches an allowlist of local patch rejections inside the existing attempt loop; feed that feedback, unchanged current revision, applicable source review and rejected proposal to the next correction generation if one remains. Unknown/stale revision, stop, job-budget, provider operational errors and unavailable source state do not become automatic correction retries. Structured response validation can be reported safely, but this pass adds no generic model-schema repair loop.

Add typed `additional_target_requests` to the correction result. A request includes pinned `base_revision_id`, existing actionable extraction `issue_id`, exact existing `target_id`, `floor_id`/collection, positive-area source evidence and a specific explanation of why that target must change to address the issue. It is a request, never authority. Reject unknown/deleted/cross-floor targets, invalid source identities/pages, non-overlapping relevant source context and empty rationale before a reviewer call. A line-shaped target citation may intersect a contextual area; do not demand area overlap from a legitimate `BoundaryRegion` line.

A proposal may contain operations and requests together. Hold the entire proposal until all requested scope decisions are processed; never publish or partially apply its already-authorized subset. The reviewer receives original page images, relevant inspected crops, actual current IFC overlays/inventory, existing issue/authorized IDs and the requested exact IDs with rationale. It returns a typed pinned decision for each request: approved/denied/unclear plus original-source evidence and reason. Require exactly one decision per request; reject missing, duplicate or foreign request IDs. Validate decision membership, revision, IDs, source refs and evidence; a model cannot grant an unrequested ID, create a new issue, replace the base review or grant a region wildcard. Existing region-scoped behavior is not widened by this path. Approved targets augment only the applicable issue in a server-owned, job/revision-scoped authorization record, leaving the original review intact. Denied/unclear requests do not grant authority. Partial approval does not filter or salvage the patch: if any held operation still lacks authority, the entire patch rejects atomically.

After approval, rerun ordinary strict patch application on the held proposal with those exact supplemental grants. A further correction generation is needed only if the proposal still needs revision, and only if an existing attempt remains. Authorization does not establish correction correctness: normal local validation, deterministic generation/reopening, regression checks and source/candidate review must still pass before publication. A request-only response on the last attempt cannot manufacture a later attempt. Changed revisions invalidate pending requests/grants and recoverable feedback; none can be reused after a CAS revision change. Persist request/decision/feedback provenance and preserve prior published state on rejection, restart, stop or late completion.

Never attach findings from an unrelated revision or silently treat absence as no defects; compare both actual scenes and originals.

The typed candidate assessment must distinguish support for the requested delta, source conflicts, newly introduced regressions, pre-existing findings and unresolved attribution/causality. Existing `candidate_supported` stays a publication requirement; never flip false to true in code because an issue looks old. The provider instruction/schema should require its decision to concern the requested change and new regressions, rather than global model completeness. A false/unclear delta assessment, conflicting source fact or new regression rejects the candidate. Missing required candidate-assessment structure fails closed; it is not supplied by a permissive default.

Preserve prior findings in revision/job history and in the current public issue list unless an explicitly source-supported resolution links to the prior issue. A newly discovered defect visible unchanged in both scenes can be classified pre-existing without inventing prior reviewer coverage. Do not trust issue IDs or prose alone: use actual source/object links and local delta. Carry forward known unresolved items even if a candidate reviewer omits them. Successful attributed-height refinement may coexist with these open findings and must not become a completeness/accuracy claim.

Keep current local loss/frame checks and strengthen the change comparison only where necessary for this scope: no disappeared IDs, new loss of geometry, altered source refs/provenance, unintended XY/footprint/host changes or source conflicts. ### D. Progress and outcome semantics

Each correction-generation proposal consumes the current configured attempt budget, whether applied, rejected, empty or request-only. Scope-review calls use existing review-call limits and the remaining job deadline, are recorded within that proposal's attempt, and never create extra proposals. No call starts after stop/deadline or when its result cannot be used within remaining workflow authority. Persist attempt phase and result so recovery history survives restart; interrupted jobs do not auto-resume inference.

Replace prose-sensitive repetition checks with canonical material-state keys: current revision/description hash, authorized scope, requested metadata/object delta, stable rejection code/locations/targets and grounded unresolved issue structure. Ignore shuffled issue order, random model IDs and paraphrasing. Valid label/host/source-semantic corrections can be meaningful even without mesh movement. Passing local validation, receiving a genuinely new reviewed target grant or publishing a supported material change permits the next already-budgeted step; these are workflow progress, not proof of factual accuracy. Identical rejected material proposals/requests with the same authority/feedback stop without another blind call. Empty/no-op corrections produce an accurate unresolved result rather than success or an infrastructure failure. Keep explicit last-usable-revision and accepted/unaccepted candidate distinctions.
