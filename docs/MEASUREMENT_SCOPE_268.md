# Explicit measurement scope — colorful-268

The reported question was: “based on my measurements, what is the footprint of the whole building seen in the blueprint”. Both selected source measurements were saved as 3 m, pinned to the current source/model revision, and both exact IDs were attached to that saved user turn. This was not an attachment or missing-value problem.

`source_only_question` treated the incidental phrase “in the blueprint” as a source-only request. This overrode the router's permitted scope in the coordinator and retrieval helpers, after which the worker context deliberately stripped the annotations' value/unit/label. The resulting answer incorrectly described the physical values as absent.

The shared guard now gives explicit source-only instructions and exclusions precedence, then honors an explicit request to use supplied measurements, then retains the existing source-authority fallback. The same input-reference grammar is used for positive and negative forms, including “my marked dimensions” and “the measurements I supplied”. This avoids both silent stripping and a negation bypass. The router, tool count, model configuration, user-value arithmetic and selected-annotation boundary are unchanged.

For permitted selected source measurements, answering/review context also includes server-derived pixel spans and reference scales, computed with the original page aspect ratio and existing physical-unit conversion. They retain the exact user value/reference and explicit user provenance, are not printed scale facts, and are excluded from source-only/native-model context. No global scale is chosen, no consistency threshold or new gate runs, and no source/model/mark is changed.

Live verification exposed a separate execution limit: two advanced answer calls returned upstream HTTP 504 near their 90-second per-call deadline. An existing-setting experiment with 150 seconds produced a validated initial answer in 120.395 seconds, proving that the old ceiling could be restrictive; its correction then exhausted the unchanged overall budget and was not accepted. Advanced agent initial/corrective drafts can now use the remaining existing `QA_TOTAL_SECONDS` budget (default 180), while basic and legacy defaults stay at 90. `GEMINI_AGENT_ANSWER_SECONDS` optionally sets an agent-specific ceiling. The total Q&A deadline, model, thinking level and token allowance are unchanged; timeout failures stay operational, never insufficient evidence.

Regression checks cover the exact question and outline paraphrases, both 3 m values reaching the answering worker and independent review as separately attributed user inputs, printed-source requests excluding numbers, explicit negative requests excluding the same grammatical references, forged source-only attribution rejection, and unselected saved marks remaining excluded. These are deterministic fixtures, not live inference or a numeric footprint-accuracy result.

An isolated proof of concept with the derived context completed the exact question in three real calls: route, worker (76.967 seconds), and supported answer review (0.881 seconds). Its supported unclear response explicitly cited both 3 m values and requested horizontal-versus-vertical calibration clarification. That experiment injected the proposed context in a private harness; final non-injected production-path replay and frozen release checks are recorded separately after completion. A drawing marked not to scale and inconsistent calibration may still require a stated assumption or clarification; recognition of entered dimensions does not make an arbitrary whole-building area factual.

The final production path was replayed without context or generation-parameter injection. It returned a targeted clarification in two real calls: routing (3.876 seconds) and the unchanged advanced model (24.007 seconds), with the actual service supplying both 3 m marks and their derived scales. It offered horizontal, vertical or independent-axis scaling, without the previous false missing-values claim or an invented building area. Clarification is not a reviewed factual footprint answer.

Forcing high thinking on every advanced request also proved unnecessary for this case: production high effort could exceed the three-minute budget, while model-default effort completed the same clarification. Advanced QA now omits `thinkingConfig` by default; `GEMINI_ADVANCED_THINKING_LEVEL` optionally selects a declared SDK level. Basic QA remains low effort, and the selected models, output allowance, overall deadline, rendering and interpretation policies are unchanged. Initial and corrective agent drafts share the selected effort policy. These observed latencies are samples rather than a benchmark or guarantee.

Independent final backend review cleared 170 combined timeout/thinking/scope/calibration/service/SDK/calculator/render checks. The deployment and integrated UI results are recorded after the combined release is verified. Private replay artifacts are under `/tmp/junction-measurement-268/`; no source upload, provider body or dataset answer is committed.
