# Progressive source-grounded building product

The active specification is [PRODUCT_SPEC.md](PRODUCT_SPEC.md). It supersedes older exclusions of persistence, background jobs and review loops. Preserve the current configurable reconstruction model; Hydrogen was not adopted. No general-purpose agent runtime, database, external rendering service or new dependencies.

## Reviewed checkpoints and ownership

1. Frontend ports the existing concept renderer selectively from the read-only concept worktree. Keep current inspection fixes. Add source/proposal picking and disclosure, footprint containment/fallback, a keyed decoration ledger, offscreen preparation and atomic viewer swaps. Preserve camera, target, modes, floor, separation, cutaway, assumptions and surviving selections. Never mutate reasoning/export data.
2. Root owns filesystem building bundles, content identity, immutable revisions, CAS publication, stable object IDs and frozen source frames. Store original bytes/pages, descriptions/native records, reasoning, IFC, scene, mappings, assumptions, findings and pipeline metadata. Restore existing artifact IDs and exact descriptions. New server-owned IDs survive insertion/reordering; deleted IDs are tombstoned.
3. Backend owns shared reasoning and native IFC extraction: complete semantic identity catalog including geometry-less objects, properties/quantities/units, supplied relationships, explicitly calculated summaries, missing/coverage records and original references. Drawings keep fallible interpretations plus original visual evidence; generated IFC never becomes native factual evidence.
4. Root owns the lightweight background runner/API; backend owns model review/patch hooks and actual-IFC overlay images. Publish initial usable preview before review, accept only targeted source-supported patches, reopen candidate geometry, audit disappeared/unresolved objects and review regressions. Preserve best revision on failure, stop, stale result, no progress or budget exhaustion.
5. Backend owns reviewed QA: pinned revision, relevant structured/source context, existing sufficiency gate, internal draft, deterministic references/units/calculations, one four-way Decisions support judgment, one meaningful repair and second review if necessary. No published unreviewed claim or repeated paraphrase-until-approval. Root integrates asynchronous progress and final highlight revalidation; frontend keeps exploration usable.
6. Root integrates all acceptance flows; independent reviewer checks code and directly uses browser/original overlays. Separate live inference from fixtures and report source-fidelity failures without hiding earlier usable artifacts.

Planner and independent reviewer approved checkpoint 1 and the full plan after one clarification round. Reviewers do not implement their own reviewed paths. Root owns contracts/commits. Frontend owns static files and focused browser tests; backend owns reasoning, review schemas, provider adapters, QA service and focused tests. Existing unrelated worktrees/untracked files remain untouched.

## Shared contracts

- `Document` pins original `source_bytes`, pages, `description`, JSON `reasoning`, building/revision identifiers, monotonic revision number, identity/frame registries and transient question context. `snapshot()` deep-copies interpretation/context and shares immutable source bytes/pages.
- `Scene` retains old fields and adds optional building/revision/parent identifiers, monotonic `revision_number`, and `review_status`. UUID identifiers are never ordered. Viewer candidates capture the current base; stale commits fail. Polling may skip intermediate revisions, so a new scene need not have the displayed revision as its immediate parent.
- All description records gain optional server-managed `persistent_id`. New initial/inserted IDs are assigned by code, never trusted from the model. Existing imported IDs survive migration; immutable target IDs and tombstones prevent reassignment. New artifacts persist identities/frames with a versioned manifest; old artifacts remain readable.
- Ordinary bbox edits do not alter stored floor transforms. Supported orientation/calibration changes require explicit source-backed transform updates. Page-relative scale and cross-page schematic status remain intact.
- `review_reconstruction(document, description, scene, previous_description=None, previous_scene=None, previous_review=None)` examines original full pages/regions plus actual reopened-IFC overlays. Findings identify stable IDs/source, discrepancy, category, evidence, action and uncertainty.
- `patch_reconstruction(document, description, scene, review)` returns a base-revision-bound list of typed add/replace/remove record operations with source evidence and reasons; never executable code. Floor replacement cannot rewrite nested collections. Candidate review and local disappearance/source checks must pass before CAS publication.
- `review_answer(document, question, draft, gate, crop, validation=...)` returns supported/contradicted/unsupported/unclear. `revise_answer(...)` must add actual evidence, repair a bound calculation/citation or narrow/remove unsupported claims. Same-assertion rephrasing is not progress. A model reviewer corroborates, never certifies accuracy.
- Native reasoning may reference storeys/openings/relationships absent from render meshes. Citation validation uses faithful reasoning records; highlighting uses conservative source associations. Complete object catalog, selected context coverage, property coverage and geometry availability are separate states. Calculations resolve source values and units in code; missing inputs never become a complete total.

## Explicit operating budgets

Communicated as design choices, not external limits: background reconstruction call 300 seconds / 65,536 output tokens, whole job 900 seconds, at most two targeted patch attempts; reconstruction review 120 seconds / 16,384 tokens. QA total 180 seconds, existing 45-second per-call ceiling clamped to remaining time, at most two post-draft reviews and one meaningful correction, retaining one targeted unclear inspection. Configuration can change these limits explicitly; exhaustion means processing stopped, not source insufficiency. No new floor/room/vertex/feature caps. Existing upload/IFC safeguards remain unless separately justified.

## Acceptance audit

Every requirement in PRODUCT_SPEC remains in scope. Track live versus fixture evidence for: concept integration and safe proposals; restart/repeat-upload reopening without inference; stable ID/coordinate insertion/reorder; preview during review; source-backed correction; rejected regression; atomic no-camera-reset replacement and retained controls; stale job/patch/QA handling; source/assumption portability; genuine IFC JSON/count/property/relationship/geometry coverage including geometry-less objects and incomplete totals; drawing QA citations/highlights; actual-height refusal; meaningful post-draft repair/uncertainty; before/after original overlays for both unchanged examples; comparative QA outcomes, usage and latency; real browser performance and software limitations; focused commits and reproducible saved-building demo.

Architecture or mocked success alone is not completion. Preserve known fidelity limitations and failed live experiments. Finish only after integrated verification and no unreported blocking review findings.
