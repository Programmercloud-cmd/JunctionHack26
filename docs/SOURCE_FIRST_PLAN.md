# Source-first iteration implementation plan

Status: independently reviewed and approved in round 1; no planning blockers. Reviewer explicitly confirmed source/revision compatibility, optional geometry, unknown-scale supplied heights, cached append, artifact portability and actual-IFC elevation requirements. This plan implements all twelve authoritative attachment requirements; it supersedes older single-source, automatic-reconstruction, new-format exclusion and no-commit instructions where the newer user request differs. Gemini and its configurable reconstruction model remain unchanged. Focused milestone commits are authorized; pushes are not.

## Scope and design choices

Keep the existing one-process FastAPI, plain browser JavaScript, filesystem bundles, original evidence, shared description, deterministic IfcOpenShell generator, reviewed QA and concept renderer. Add automatic source interpretation, explicitly requested optional geometry, incremental multi-source buildings, source-linked conversation/clarification, editable attributed values, coherent floor presentation, diagnostics and a separate format adapter track. Preserve V2–V4 artifacts and saved bundles.

No arbitrary source/object/vertex cap is proposed. Existing per-file normalization/provider/job limits remain visible and must be reported individually; do not reinterpret the historical five-page per-file bound as a five-page whole-building bound. Existing 25 MiB portable IFC bound may prevent embedding large multi-source sets: report that export limitation without losing the local bundle or blocking QA. Existing configured correction/call budgets remain; extraction alone must not spend reconstruction-review/repair calls. Root must communicate any necessary changed budget before live calls. Local resource isolation for SVG/DXF protects the renderer from active content/external resources; it can reject drawings relying on external assets, so report unsupported features explicitly. These are implementation choices, not claims about source validity.

Exclude detailed roofs/domes, photorealism, Blender/cloud rendering, auth/database and autonomous runtime agents. Unknown geometry stays unresolved. SVG and DXF are now included; DWG support depends on an actually verified converter and must never be advertised speculatively.

## Evidence from current implementation

- `BuildingStore.add` uses original SHA256 as building ID and one building-level source/pages manifest; immutable revision files do not yet pin source membership.
- `reconstruct_scene` saves description only after generate/reopen. `build_reasoning` derives drawing objects/floors from scene rather than interpretation.
- `JobRunner` combines extraction, geometry and review, with generic failure text implying an earlier model even on first failure.
- Existing stable IDs, frame registries, atomic CURRENT publication, candidate retention, original-page overlays and source-only drawing QA are reusable.
- `generate_ifc` explicitly gives every floor elevation zero; metric-only alignment disallows supported registration of unscaled diagrams. The viewer already adds an independent exploded offset but cannot repair missing building elevation.
- Existing `segment` plus thickness-band walls cannot faithfully represent every tapered/angled end. Diagnose actual outputs before choosing schema or generator corrections.

## Shared contracts (freeze before dependent implementation)

### Source identity and revision membership

A building keeps its existing 64-hex `building_id` (initial source hash); adding files never changes it. A `source_id` is SHA256 of original bytes, independent of filename. Source metadata includes original bytes/hash, display filename aliases, media kind, normalized page hashes/dimensions, normalization mapping/diagnostics and optional vector metadata. Deduplicate resources and successful interpretation by source identity, including reuse across buildings; do not reuse a source result conditioned on another building's context as independent extraction.

Each immutable revision saves a `sources` manifest. Entries map `(source_id, source_page)` to an append-only building `page` number, with the original normalized page pixels and coordinate mapping. Never renumber earlier pages. Internal `Page` and public page descriptors add `source_id`, `source_page` and source filename; existing `page` remains the canonical legacy selector. A source extraction cache uses source-local pages; merge explicitly remaps every source reference into the building page namespace and assigns building-stable object IDs. Geometry/review caches are keyed to their input revision, not merely original file hash.

References retain existing `{page,bbox}` and add optional `source_id`/`source_page`; server resolves legacy refs against that revision's manifest and rejects conflicting combinations. Every normalized bbox remains in the displayed original page frame, never the building frame. New evidence URLs are revision-pinned; existing unversioned routes remain compatibility/current routes. An older answer resolves its own source manifest, not CURRENT's source list. Legacy bundles synthesize one source entry on load without rewriting old revisions.

Native IFC keeps original GlobalId/property evidence per `source_id`; model record identity must include source identity when different IFCs repeat a GlobalId. Drawing-derived IFC restores drawing sources and cannot enter native factual shortcuts. Multi-source drawing ingestion is the main UI flow; mixed/native source catalogs retain per-record evidence rules rather than converting native objects to floor polygons. Never silently overwrite or fuse conflicting source facts.

### Shared interpretation with optional geometry

Extend `BuildingDescription` additively, not with a second incompatible reasoning pipeline. Retain floors, original labels, source refs and existing persistent IDs. Allow semantic records without geometric traces: empty/absent polygon/segment fields mean geometry unavailable, not empty evidence. Add source-linked observations/measurements for all view types, including section/elevation facts; only actual floor plans instantiate floor geometry. Expose extraction coverage and per-source completion. Preserve exact returned validated interpretation before any generator call.

Provider interface: `extract_interpretation(document, *, include_geometry=False)` returns the shared schema. The source-first prompt requests useful semantic observations, view classification, labels, measurements and evidence regions without exhaustive wall/feature polygon tracing. Geometry action reuses that interpretation and requests only missing geometry/relationships through the same schema and typed patch workflow; existing full descriptions require no re-extraction. Existing `reconstruct` may remain a compatibility wrapper. Reasoning object/floor records derive from saved interpretation independent of scene; optional scene associations enrich them without becoming factual evidence.

Source extraction operates independently per new source so adding B does not re-extract A. Building integration combines cached source interpretations deterministically; repeated views of a floor must not silently create additional storeys. Merge only source-supported floor equivalences, retain all supporting refs, and mark uncertain alternatives/conflicting dimensions explicitly. Explicit geometry/refinement can inspect multiple originals for cross-source relationships/conflicts. Persist interpretation identity/provenance and missing geometry; no geometry work or reconstruction review on default extraction. Missing interpretation records never establish missing source objects.

Revision payload adds `interpretation_status`, `geometry_status`, and `geometry_revision_id` where retained geometry belongs to an older interpretation. QA pins the current source/interpretation revision; UI explicitly identifies any retained older model, and highlights only validated associations. Publication of extraction must never relabel an older scene as regenerated against new evidence. Successful JSON survives a geometry error, restart or stop. Source-only revisions are first-class successes.

### Jobs, atomicity and APIs

Keep current routes. `POST /api/documents` accepts existing `file` and additive multi-file `files`; source-first upload queues automatic extraction server-side for genuinely uncached drawing sources. `POST /api/buildings/{id}/sources` adds related files to the selected building. Return source list, per-source statuses, extraction job IDs, revision identity and `has_scene`. A duplicate upload/reopen returns cached state without inference; interrupted or failed extraction requires an explicit retry, not surprise reprocessing.

Add `POST /api/buildings/{id}/extraction` for explicit retry. Existing reconstruction endpoint is the explicit Generate 3D/Refine action. Coalesce repeated requests for the same source/operation. Persist source additions before launching inference. Workers extract against immutable source snapshots and save cache results even if their publication base became stale. Under the store lock, merge an unchanged per-source result into the newest source manifest; if related interpretation/user values changed, preserve the candidate and require a deliberate rebase/review. Geometry/refinement still uses compare-and-swap on base revision. No worker may drop newly appended sources or user edits. Stop/restart guards prevent late publication.

Job diagnostics persist `phase`, safe `error_stage`, `error_category`, opaque diagnostic ID, usage and whether a prior model actually exists. Stages distinguish ingestion, extraction provider, interpretation validation, geometry enrichment, IFC generation, reopening and review. Save returned structured outputs privately for deterministic replay; never log raw requests, credentials, source content or provider exception strings. First-model failure says sources/interpretation were saved and no model was generated; only say retained model when one exists.

### Conversation and clarification

Persist conversation messages within the building bundle, each with ID, role, timestamp, input/question, revision, job ID and final result. `AskRequest` adds optional `conversation_id`, `reply_to` and structured `clarification_response`; old callers remain supported. Client sends a message reference, not untrusted assistant evidence. Server retrieves relevant prior turns and explicit selected scope as fallible conversational context; originals and current revision provide factual support.

Question jobs may complete with a distinct typed `clarification` result `{message, suggestions, free_text_allowed:true, reply_to}` rather than an `insufficient` answer. Resolve materially ambiguous intent before the evidence gate, using a small provider intent-routing response; do not impose clarification when a stated reasonable scope suffices. Reuse existing question execution budget and expose this call in usage. Source insufficiency remains the three-way sufficiency gate. Clarification replies preserve intent context without treating earlier assistant assertions as sources.

Final answers retain reviewed status, original citations, native records, calculations, uncertainty and review outcome. UI shows meaningful phases and an expandable Evidence and checks view, never private chain-of-thought or unreviewed drafts. Chat citations load the answered revision's source even without 3D; conservative object links respect current view and preserve camera/orbit. Old messages remain accessible after revision changes and restart.

### Editable attributed inputs

Add immutable revision `user_values` records with ID, scope `{floor_id?,object_id?}`, property, typed value/unit, provenance `user_provided`, optional original evidence/source document ref, reason, base revision and submission identity. Shared assumption rows are computed/grouped by scope+property; distinguish `observed`, `inferred`, `display_assumption`, `unknown`, `user_provided` without changing observed source facts in place. A supplied height never calibrates XY. With unknown horizontal scale, retain the actual supplied height and unit for attributed QA, keep the scene unscaled, and disclose the separate display conversion used for vertical presentation; never treat relative plan units as metres.

`GET /api/buildings/{id}/assumptions` returns grouped rows and editable property descriptors. `POST /api/buildings/{id}/refinements` accepts `{base_revision_id, edits:[...], supporting_source_ids?:[...]}` and returns a job. Validate finite values, supported unit dimensions, scope, source refs and revision before publication; reject executable/arbitrary paths. Supported properties cover storey display/known height, source-referenced plan calibration, stair connectivity and source-linked interpretation corrections through typed patches. Ambiguous corrections remain reviewable inputs, not assumed facts. Do not silently ignore unsupported properties.

Apply and refine persists submitted provenance, assesses source conflicts, changes affected deterministic geometry or uses bounded targeted model review where interpretation is required, then atomically publishes accepted updates. Failed candidates retain submitted values/diagnostics separately plus the prior usable revision. No call on editing/keystrokes. Exports/reopen preserve user values, edits and source identity in additive versioned artifact metadata with V2–V4 readers retained. The new artifact manifest also embeds original source bytes with hash/media kind, normalized pages and source-local mappings/vector metadata, so reopening preserves supplied SVG/DXF originals as well as visual evidence. Existing artifact-size validation remains; if the portable artifact cannot contain these sources, report that export as unavailable while retaining the complete local bundle rather than exporting provenance loss. QA can use user values with explicit attribution for appropriate questions, but drawing-only height questions still refuse unsupported source facts.

### Geometry and viewer

Keep three transforms separate: original page→local floor plane, local floor→building placement/elevation, and viewer-only exploded spacing. Preserve frozen source frames and shared-page scale. Permit supported registration in an unscaled common page frame without asserting metres: matching stair/exterior anchors with inspected evidence can establish translation/rotation; never independently scale floors or equalize footprints. Cross-page scale uncertainty remains explicit. Add source-linked registration/stair relationships with status and provenance; unsupported registration stays schematic.

Generate real storey elevations from supported values or explicitly attributed display spacing in the appropriate display unit. Stacked mode retains them; exploded mode adds spacing. Stair connectivity can use a continuous schematic ramp/flight between established storeys while recording unknown rise/vertical dimensions. Preserve source footprints and the larger terrace; do not introduce a connection from similarity alone. Export/reopen retains base elevation, relation and provenance. Source overlays inverse-transform actual reopened geometry, including building placement, to original coordinates.

Native scene floors derive from supplied storeys/containment even when storeys have no geometry. Missing/ambiguous containment remains visible without inventing a floor. Replace cutaway boolean with 0–100 slider: each selected floor uses its base elevation and supported height, or labeled display reference. In all-floor mode apply the same percentage independently to each storey's reference; uncontained geometry uses an explicitly displayed scene-wide reference. Use clipping planes in inspection and concept modes; do not rescale walls or move openings. Preserve percent, floor, mode, camera and selections across revision swaps.

Investigate wall/opening failures using retained descriptions, host keys, source segments, signed wall bands, transforms and actual reopened meshes. Structured local consistency findings identify duplicate/conflicting hosts, contradictory floor/stair relations, invalid projections and missing geometry, with source refs; they guide source review, not automatic nearest-wall snapping. If actual tapered walls need a richer representation, add optional source footprint polygons to the existing wall record and deterministic extrusion/void logic, retaining segment/band compatibility. Use real source evidence to distinguish extraction error from generator/display error.

Dependencies proposed to root in `requirements.in`; root resolves lock. SVG first; DXF next; DWG only after verified conversion path. Integrate independently reviewed commits, never a wholesale worktree replacement.
4. **Independent planner/reviewers:** plan reviewer read-only; implementation reviewers read-only against changed paths and acceptance evidence. Reviewer must not review own implementation. Direct browser interaction, original overlays and reopened IFC checks are required, not screenshot-only agreement. At most two plan review rounds, then root resolves remaining scope/architecture disagreements; implementation blockers must be fixed or explicitly reported.
