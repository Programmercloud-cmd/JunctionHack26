# SVG and DXF source normalization

The source adapter is `app/source_formats.py`. The application integration owns upload routing, original-byte persistence, content identity, citations, shared reasoning, QA and optional reconstruction. The adapter never calls a provider, serves vector markup, establishes building calibration or generates IFC.

`normalize_vector_source(data, filename, max_edge=4096)` returns `NormalizedVectorSource(pages, warnings, metadata)`. Pages are RGB Pillow images, ready for the existing PNG source-preview path. The caller must preserve the exact original bytes and JSON metadata, including through content-cache reuse and portable export. Metadata `pages` corresponds one-to-one to rendered images; `source_page` is one-based within that source file. The building bundle supplies global source identity. Each page records actual normalized pixel dimensions and an affine `source_to_normalized` using SVG order `[a,b,c,d,e,f]`: `u=a*x+c*y+e`, `v=b*x+d*y+f`. Citations use the existing normalized PNG coordinates.

SVG retains original viewBox, viewport and document dimensions; its affine accounts for nonzero viewBox origins, `preserveAspectRatio` meet/slice/none, letterboxing and root transforms. Mapping uses CairoSVG computed style nodes, so inline styles, class rules and CSS precedence match the rendered coordinates. Transform-origin mappings that are not supported are explicitly null with warnings; normalized PNG citation coordinates remain usable. Text records retain original text, attributes, ancestor transforms and local-to-normalized transforms, including nested SVG viewports. A text anchor is not a text extent: unsupported list-valued positioning has no fabricated anchor and exact glyph bounds are not claimed. Referenced symbol text is preserved in the original vector but metadata is not a complete visible-instance text catalog. SVG millimetres, points and pixels are document presentation dimensions, never evidence of actual building scale.

SVG rasterization uses CairoSVG on the server. Only PNG/JPEG data resources can be decoded locally; network and filesystem resources are never fetched. External image/use references are omitted from the rendering copy with warnings. CSS imports/fonts, XML stylesheet references, unsupported embedded resources, scripts, animation, foreign objects and unsupported filter primitives are reported. External XML entities reject rendering explicitly. Original bytes remain the caller's preserved source, untouched by rendering sanitization. This local-only rule can omit externally linked labels or imagery from otherwise valid drawings; a self-contained SVG or PDF export is the useful alternative. Static font substitution and advanced font-layout differences are disclosed. No browser receives raw SVG markup.

DXF uses ezdxf's native SVG backend, then the same PNG adapter. Every nonempty supported model/paper layout is rendered separately; there is no automatic five-layout cap. Layouts without a renderable 2D extent remain in `unrendered_layouts` with source handles and warnings. Source layer names/on/off/frozen state, declared `$INSUNITS`/`$MEASUREMENT`, entity handles/types/layers, available bounding boxes and original text remain metadata. The renderer's actual transformation matrix supplies mapping, including the DXF upward-Y to image downward-Y conversion. Units are retained as declarations, not silently applied as physical calibration. Text in inserted blocks is preserved in original bytes and the rendered image; the top-level text list is not a complete semantic catalog.

DXF previews fill the existing 4096-pixel maximum edge independently of model-unit magnitude. The backend's relative stroke-weight policy preserves drawing-weight ordering without pretending to know the plot scale. The preview warns about this display choice. ACIS solids, non-top-view 3D, external references/images, OLE and some text/viewport conventions are unsupported or schematic. Unsupported/skipped entities retain handles where available. External raster loading is disabled before the backend can open local paths. A local RenderContext override also replaces every string plot-style reference with an in-memory default before construction, layout selection or viewport rendering can call the filesystem loader. Original references remain in per-page external_resources metadata with not_fetched status and an explicit warning.

DWG is not supported. The actual local availability check found neither `ODAFileConverter` nor `dwg2dxf`, and no DWG conversion was run. Even discovery of an executable does not automatically advertise a validated conversion path. Export to SVG, DXF or PDF remains explicit guidance.

## Dependencies and verification

The coordinated additions are `CairoSVG>=2.9,<3` and `ezdxf>=1.4,<2`; the experiment resolved CairoSVG 2.9.1 and ezdxf 1.4.5. CairoSVG additionally needs system Cairo (`libcairo.so.2` exists in the development environment). Tests were run with the existing Pillow constraint using Pillow 12.3.0 in an isolated temporary environment. Root owns the reproducible requirements lock.

Focused deterministic tests cover viewBox origin/aspect modes, root and nested transforms, physical-unit non-calibration, preserved labels, no network/file fetching, blocked XML entities, unsupported-feature warnings, DXF layers/units/handles/text/Y inversion, multiple layouts, external image blocking and explicit DWG rejection. Independent review found and reproduced two blockers: DXF plot-style file loading and incorrect metadata under SVG CSS transforms. Both are fixed and covered by modelspace/paperspace/viewport no-read tests and inline/class/important/root CSS coordinate tests. The expanded focused suite passes 23 tests; independent re-review remains separate.

Actual source comparisons used unchanged `data/ifc_models/kit-institute_ac20-institute-var-2_plan-02-erdgeschoss.svg` and `..._section-east-west.svg` against their same-stem PDFs. Direct inspection found matching wall linework, door swings, room labels, stair/level relationships and proportions; fonts/antialiasing are not pixel-identical. SVG results were 1678×818 and 2449×774. New inputs were Wikimedia `10310816.svg` (rotated Cyrillic labels and temple plan), `100075564.svg` (viewBox-only religious/column plan) and Swiss Dwellings `site65_bldg3_floor5.dxf` (429 source entities, 88 top-level text records). No `questions.jsonl` was read.

The Swiss example exposed two real defects during verification: natural millimetre SVG sizing created an unreadable 92×64 preview, and absolute CAD plot weights obscured fine symbols. The final preview uses 4096×2837 pixels and disclosed relative stroke weights. Temporary comparison artifacts are under `/tmp/junction-formats-verification/`.

This adapter verification does not establish integrated QA, inference caching, portable source export or optional reconstruction fidelity. Those require the application-level acceptance checks and independent browser review. No live-provider claim follows from these local renders or deterministic tests.
