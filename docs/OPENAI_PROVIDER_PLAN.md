# Explicit OpenAI provider — bounded implementation plan

Status: independently reviewed and implemented; final publication verification is recorded in [OPENAI_PROVIDER.md](OPENAI_PROVIDER.md). The user requests OpenAI as an explicit alternative to Gemini, localhost availability notification as soon as the core path is testable, then publication to the existing agentic demo. No automatic provider fallback.

## Core contract

- `AI_PROVIDER=gemini|openai` selects one settings profile and provider factory; default remains Gemini. Invalid selection or missing selected-provider credentials produces a safe configuration error before inference. An OpenAI-only installation does not require a Gemini key for core inference.
- Root verified account availability and real structured Responses probes for `gpt-6.1-sol` and `gpt-6-luna`. Use Sol for advanced/Hydrogen and legacy reconstruction roles; Luna for basic/Flash, routing, UI and Decisions-equivalent roles. Keep role-specific OpenAI model overrides separate from Gemini overrides. Do not substitute model IDs from memory or silently change the selected model after an error.
- Add an OpenAI Responses adapter using the existing provider method surface, prompts, evidence payloads and canonical schemas. Reusing/subclassing Gemini's shared high-level methods is acceptable when OpenAI construction, transport, Decisions, selected-role budgets and cleanup are overridden; no Gemini SDK client/request may be created on the OpenAI path.
- Cover conversation, agent routing, basic/advanced answering, shared UI, legacy intent/gate/crop/answer, interpretation, reconstruction/enrichment, user-input refinement, reconstruction reviews/target authorization/patches, answer review and correction. A normal OpenAI model emits the same validated Decisions choice/confidence contract, including nullable confidence where the existing caller expects it; it is not a new sufficiency preflight.
- Adapt canonical JSON Schema only for supported OpenAI strict wire syntax: object closure/required fields, union/discriminator forms and tuple representations as necessary. Parse and validate every result against the original canonical Pydantic/domain contract afterward. Transport adaptation must not silently drop source references, operations, floors or valid feature scope. Reject unsupported schemas explicitly rather than accepting unvalidated JSON.
- Convert the existing original-page/crop/extra-view image inputs into Responses image parts without changing source authority, revision pins, exact question, user-value attribution or QA-context isolation. Retain original image selection/normalization rules.
- Preserve usage/call-stage reporting, safe operational errors and cleanup. Incomplete/token-limit output, refusal, malformed JSON, schema rejection, timeout, unavailable model, authentication and transport failures never become evidence-insufficiency answers. Keep SDK retries/fallback off; existing orchestrator retry/Stop policy remains authoritative. Never expose provider bodies, credentials or private thoughts in logs/errors.
- Preserve normal QA review/correction counts and the fixed render creator plus two independent parallel reviewers on the exact same reopened candidate. Keep existing per-call/QA deadlines and uncapped render-round/Stop behavior; no new cumulative caps, geometry rules, inference calls or tool routes.

## Optional selected-provider transcription follow-up

Core localhost notification need not wait for this follow-up. Under OpenAI, select batch speech recognition through `gpt-transcribe`: buffer existing PCM16/16kHz recording, submit on explicit Stop, emit one final transcript and terminal event through the existing websocket contract. No interim transcript is promised. Use the documented prompt plus keyword/languages-array contract; keywords are spelling hints, not required words. Explicit configured legacy transcription models keep their corresponding singular-language contract without fallback. Finnish/English, noise and measurement-recognition quality remain unverified; users review/edit before Send. Gemini keeps its current live adapter. Readiness follows the selected provider/key/model; no hidden Gemini requirement or fallback. Preserve editable drafts, explicit Send, cancellation/disconnect cleanup, timeout and safe errors. ElevenLabs output remains unchanged. Keep frontend layout and microphone interaction unchanged.

## Ownership

- Root: settings/factory integration and call sites, dependency lock (`openai==3.51.0` plus resolved dependencies), environment/example configuration, health/doctor labels, docs, local/public verification and deployment. Root handles actual credentials without printing them.
- Adapter implementer: new `app/providers/openai.py` and focused adapter tests only; coordinate any shared Gemini-method edit with root before touching it.
- Optional voice implementer after core review: `app/voice_config.py`, `app/voice_providers.py`, minimal voice factory/readiness hookup and focused tests; coordinate `app/voice.py` ownership first.
- Independent reviewer: read-only plan and implementation review against the changed contracts. No agent may overwrite the other conversation's current example-copy WIP in `app/main.py`, `app/public_access.py`, `app/static/projects.js` or its docs/tests.

## Acceptance and release gates

1. Gemini remains the default, retains its models/behavior and passes relevant regressions. Selecting OpenAI routes all core provider capabilities to OpenAI only; missing/invalid configuration fails before calls and never falls back.
2. SDK HTTP interception/injected clients verify every required capability, strict schemas, text/images/crops/extra views, Decisions-compatible payloads, selected-role models/budgets, usage, timeout/truncation/refusal/errors and credential-safe diagnostics.
3. Source-first originals/revisions/annotations, typed validation, same-candidate private parallel reviews, Stop/revision guards and previous usable results remain intact. Test invalid/confident failures as well as happy paths.
4. A local OpenAI-only run performs an ordinary conversation, original-source factual QA with support review and at least one explicit render round with creator plus two overlapping reviews. UI controls remain inference-free. Notify the user immediately when localhost is usable, with address and any honest remaining verification gaps.
5. Optional OpenAI transcription passes PCM-to-final editable draft, no automatic Send, cancellation/timeout/close behavior, selected-provider readiness and missing-key/no-fallback cases. ElevenLabs output regressions remain passing. Verify SDK options against installed source/official docs before implementation.
6. Run frozen relevant backend/browser checks; distinguish fake-provider tests from successful live OpenAI calls. Publish the verified snapshot to the existing agentic demo only through root's established idle/persistence/access-preservation workflow; keep original site and all runtime originals/history/models intact.
