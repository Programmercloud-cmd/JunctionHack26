# Source reasoning and reviewed answers

`reasoning.build_reasoning(document)` creates persisted source-specific JSON. Native IFC uses original bytes and all `IfcObjectDefinition` records, including objects without meshes; it preserves original IDs, schema ancestry, attributes, property/quantity units, containment and supplied opening/fill/space-boundary relationships. It reports catalog, property, relationship and geometry coverage separately. Calculated mesh summaries identify their methods and original contributing records. Supplied model facts do not prove as-built conditions.

Drawing JSON contains the exact, fallible building description and source-linked object interpretations. Original pages remain authoritative. Generated scene properties, mesh dimensions and display assumptions are excluded from factual context. Reopening our generated IFC continues through this drawing path. Unsupported views and unresolved features remain in the interpretation; they do not become invented floor geometry.

Question retrieval retains the full original identity catalog but selects relevant detailed records/property values. It explicitly reports omitted values and record coverage. Native calculations bind object/property references to original records in code. Missing units, missing relevant containment, ambiguous property paths, out-of-scope operands and incomplete model/storey aggregates produce an incomplete result with missing inputs. Explicit partial calculations require selected-object scope; a selected subset cannot establish a building-wide total. Calculated inputs are exposed to answer review with original references.

Calculated mesh volume uses one closed, consistently oriented shell. This is our conservative implementation choice, not an IFC limitation: disconnected or nested shells need additional topology analysis to avoid cancellation or mistaken cavity handling. Such elements retain supplied volume quantities and other supported summaries, but no calculated volume. This can limit answers about complex elements. Axis-aligned extents are labeled as such, not presented as oriented dimensions. Surface area is the sum of modeled triangle faces.

Production QA captures an immutable revision, retrieves evidence, runs the existing sufficiency gate, drafts internally and validates references/calculations. Every draft answer or refusal then gets one overall support review from Gemini Decisions, which returns supported, contradicted, unsupported or unclear. Local validation errors cannot be overridden by model approval.

One correction may inspect a new source crop, expand original IFC properties, repair a calculation/citation, remove fixed server-identified claims or narrow an unsupported answer to an explicit limitation. A contradicted refusal can reassess the sufficiency gate after genuinely additional inspection. Rephrasing an unsupported assertion alone is rejected. At most two support reviews and one repair occur, under the configured QA wall-time budget; request deadlines clamp each provider call. Real stage callbacks drive the interface. Operational failures remain errors, not evidence-insufficiency judgments.

Reconstruction review receives original pages, original-coordinate overlays from actual reopened IFC geometry, the current description and candidate/previous context where applicable. Translucent overlays blend over original strokes. Patches use typed data-only operations with source references and stable target IDs; root orchestration owns identity checks, regeneration, regression review and publication.

`legacy_fixture_without_review` is reserved for explicit injected old regression fixtures; production provider adapters never enable it. Mocked SDK transport tests establish serializer/parser behavior only. Live compatibility and source fidelity require separate live runs and visual review.
